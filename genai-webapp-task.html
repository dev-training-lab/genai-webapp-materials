このタスクのゴール

  1. フロント〜API〜DBが一気通貫で動くWebアプリを、ローカル環境で起動できる状態まで作る
  2. 生成AIに「書かせる」だけでなく「相談する・レビューさせる・調べさせる」使い方を身につける
  3. AIが書いたコードも含めて、自分のコードとして説明できる状態にする
  4. 要件整理 → 設計 → 実装 → テスト → ドキュメントという開発の一連の流れを体験する

完成度よりも「理解度」を重視します。機能を盛るより、少ない機能をきちんと動かし、なぜそう作ったかを説明できることを優先してください。

共通要件

MUST必須

  • docker compose up -d で PostgreSQL が起動する
  • テーブルは Flyway のマイグレーションで作成する（手動 CREATE しない）
  • Spring Boot で REST API を実装（2テーブル以上・関連ありの CRUD）
  • DB アクセスは MyBatis で実装する（SQL は自分で読んで説明できること）
  • Next.js の画面から一覧・登録・更新・削除ができる
  • 入力チェックをフロント・バックエンドの両方で行う
  • エラー時に画面で分かるメッセージを出す
  • バックエンドの主要ロジックに単体テストがある
  • README の手順だけで、他の人が起動できる
  • リポジトリ直下に CLAUDE.md または AGENTS.md があり、実際の構成と合っている

WANT余裕があれば

  • ログイン機能（Spring Security）
  • OpenAPI（springdoc-openapi）で API 仕様を自動生成
  • フロント・バックエンドも Docker 化して一括起動
  • GitHub Actions でテストを自動実行
  • Playwright などで E2E テスト

生成AI活用のルールとコツ

① 先に自分で考える

設計方針やテーブル案を自分で書いてから、AIに「レビューして」「抜けはある？」と聞く。丸投げより学びが大きく、回答の質も上がります。

② 小さく頼む

「アプリを全部作って」ではなく「このテーブルの検索用 Mapper を」のように1機能・1ファイル単位で依頼。差分を読める量に保ちます。

③ 説明できないものはコミットしない

生成されたコードは1行ずつ読む。分からない箇所は「この行は何をしている？」とAIに質問してからコミット。

④ 公式ドキュメントで裏取り

AIは古いバージョンの書き方を出すことがあります（例：Spring Boot 2系のjavax.*、Spring Boot 3系までの@MockBean、Next.js の Pages Router）。怪しいと思ったら公式を確認。

⑤ エラーは全文＋期待値

スタックトレースを全文貼り、「何をしたら」「何を期待して」「何が起きたか」を伝える。関連ファイルも一緒に見せる。

⑥ ログを残す

うまくいったプロンプト・失敗したプロンプトを docs/ai-log.md にメモ。最終レポートの材料になります。

雛形を fork して始める

  1. Slack の申請ワークフローで GitHub のユーザー名を送る（ワークフローのリンクは案内のメッセージに載っています）
  2. Organization dev-training-lab からの招待メールを開き、7 日以内に参加を承認する（期限が切れたら、案内した人へ Slack で連絡して送り直してもらう）
  3. 雛形リポジトリ（dev-training-lab/genai-webapp-starter）を開き、右上の Fork で自分のアカウントにコピーする
  4. fork の Settings → General → Features で Issues を有効にする（fork では無効になっている）
  5. fork を clone し、backend/ と frontend/ を生成して作業を始める
  6. 最初の push のあと、fork の main から本家の main へ Draft PR を作る。タイトルは「【進捗】題材名」。マージはされず、push するたびに進捗として本家から見える

fork は Private ですが、研修の参加者には見えます。本家への進捗 Draft PR を通して、ほかの研修生や講師が中身を見られます。業務情報・顧客情報・パスワードや API キーは書かないでください。.env などの設定ファイルもコミットしません。

社内の備品・書籍の貸出管理 Web アプリ（新人研修の課題）

- フロントエンド: Next.js（App Router）/ React / TypeScript

よくあるハマりどころ

症状原因と対処
ブラウザで CORS エラー3000 → 8080 は別オリジン。Spring 側で CORS を許可するか、Next.js の rewrites でプロキシする
5432 番ポートが使用中ローカルに別の PostgreSQL が動いている。止めるか、compose の左側ポートを "15432:5432" などに変更
Flyway の checksum エラー適用済みのマイグレーションを編集した。適用済みファイルは触らず新しい V2__...sql を追加する
javax.validation が見つからないSpring Boot 3 以降は jakarta.*。AIが古い書き方を出しがちなので注意
MyBatis で Invalid bound statement (not found)XML の namespace / id が Mapper のクラス名・メソッド名と一致していないか、mapper-locations の指定が XML の場所と合っていない
AI が JPA の @Entity や JpaRepository を提案してくるこのタスクでは使わない。プロンプトに「MyBatis を使う（JPA は使わない）」と明記する
Next.js で useState が使えないApp Router はデフォルトで Server Component。ファイル先頭に "use client" が必要
日時が9時間ずれるタイムゾーンの扱い。DB は timestamptz、Java は OffsetDateTime などで統一する
